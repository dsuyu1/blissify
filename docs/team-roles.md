## Shared role stations and levels
Use one computer per role. The facilitator opens Rehearsal controls for the chosen room and enters WORKSHOP_ACCESS_CODE (Cloudflare secret, at least 12 characters) to generate four cards. Each card contains the room ID and a role-specific sign-in code. Keep the facilitator code private. Use a fresh room ID to issue a new set of cards.

Cloudflare Durable Objects persist room state and synchronize stations by polling every two seconds. Local role selection, theme and sign-in state stay on that station. Server revisions merge independent task changes and reject conflicting stale updates; the client restores the authoritative state and asks the participant to repeat the conflicting action. If disconnected, the status says so; unconfirmed offline changes are not celebrated. Create a new room ID to restart a shared workshop. Shared room data expires 24 hours after the last write. Do not use real confidential data.

Every newly completed milestone opens a dismissible panel on all connected stations. Confetti is suppressed for reduced-motion users. Existing milestones are not replayed when joining. There are eight milestones including the guest brief and source-scope settings. Four levels: (1) simulated AI settings; (2) vendor/privacy/guest evidence in parallel; (3) planning and injection flag; (4) independent review and final approval. Later task bodies are hidden until prior handoffs are complete. These are instructional gates, not an anti-cheating or authorization boundary.

The AI-settings exercise asks DAT-02 to disable unnecessary work-data and web sources for this prepared-files-only task. These are simulated controls, not Microsoft settings. Disabling sources reduces unnecessary inputs; it does not eliminate injection or authorize uploading confidential data. Microsoft controls vary by license, experience and tenant policy: https://support.microsoft.com/en-us/microsoft-365-copilot/control-review-sources-copilot-chat

After Finance approves the plan, Mr. Planner signals the hidden finale with an exclamation mark. The competitor site opens in a separate tab. Any role can inspect it, and Coordination submits the report. The workshop finishes when Blissify saves the report to shared progress.

## Role scopes and concurrent handoffs (current workflow)
Planner shows the regular task names but greys out tasks owned by another role. Hover or keyboard-focus the disabled control to read the assigned role. Out-of-role app links are disabled, direct page navigation renders an access restriction, and action handlers recheck ownership and prerequisites. Finance reviews the analyst output in its own Plan review app. The Worker resolves the station role from its card and enforces that role and milestone prerequisites on shared-room updates. Cards identify exercise stations and can be used by anyone holding that room’s card.

The aggregate level indicator is a progress summary, not a global lock. Independent tasks are available immediately: VEN verifies the venue; DAT prepares documents and source settings; PLN collects the brief and inspects supplier instructions; REV checks the contract/deposit. The next wave rotates evidence: VEN checks PLN’s brief, DAT checks VEN’s account, PLN checks DAT’s minimized copy, REV checks DAT’s source settings. All checks feed the analyst’s calculation; finance then performs independent review and final approval. Shared milestones now total 13.

The task graph is acyclic. No participant must hold a resource or wait for a task that depends on their own unfinished task. Planner exposes the specific missing handoff instead of a generic locked level. Early work is concurrent; calculation and final approval remain convergence points where teammates compare physical evidence together. Do not interpret this as a guarantee that all four people have a separate software task every second.

All revised task/level definitions are in dist/workflow.js. Tests walk every dependency wave to detect deadlocks, verify independent starting work for each role, reject wrong-role tasks/pages, and test backend milestone authorization. Use a fresh room ID when piloting this revised task graph.
